## July 10, 2026 — PostgreSQL-backed user authentication

* **Changes:** Added SQLAlchemy database configuration and a persisted user model, moved Docker Compose to the repository root, and updated registration and login to create and query PostgreSQL records. Expanded ignore rules and backend dependencies.
* **Bugs:** Reworked authentication paths that still assumed in-memory user records so database sessions and ORM users were handled consistently.
* **Verification:** The commits confirm the database module, ORM model, container configuration, and authentication changes. No exact test count or fresh-database migration result was recorded for this date.
* **Lessons:** Migrating one ownership root at a time reduces risk: persisted users establish the privacy boundary that activities, sessions, goals, and rewards can reference.
* **Decision:** PostgreSQL with SQLAlchemy replaced temporary lists for durable storage. Compared with continuing in-memory persistence, this supports user isolation and maintainability; schema migrations were deferred and therefore remained a known reliability gap.
* **Current status:** Authentication was PostgreSQL-backed. Activities, sessions, XP, goals, and rewards still required persistence migration and ownership relationships.
* **Technical debt:** No Alembic migration history existed, runtime schema creation remained, and most domains still used temporary stores.
* **Reference:** `ac81c9f`
